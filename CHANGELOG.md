# Changelog

## Unreleased

### Added

- `server_info` describes the Dockhand: its version, whether its login is on, the health of its own database and how many Docker hosts it manages
- `env_list` lists every Docker host, how it is reached, whether it is online and what it holds by state
- `container_list` lists the containers of every host or of one, narrowed by stack, name or state, or to the ones something is wrong with, each saying what
- `container_get` describes one container in full: state, exit code, health and what its latest check printed, limits, variables, mounts, ports and networks
- `container_logs` reads the end of a container's log, bounded by time or narrowed to a word, and `stack_logs` reads a stack's containers' logs as one, in the order written
- `stack_list` lists the compose stacks of every host with their containers by service
- `container_start`, `container_stop` and `container_restart`, and the same three for a stack, each with a dry run and the result read back from the host
- `env_test` has Dockhand try a Docker host, saved or not yet, and says what it found and which Hawser agent answered; `env_create` adds a host by its socket, its address or its agent, tried first; `env_delete` forgets one, after saying what would go
- `registry_list` lists the image registries Dockhand keeps, `registry_test` says whether one can be reached and signed in to, saved or not yet, and `registry_create`, `registry_edit` and `registry_delete` save, change and forget one
- `registry_images` lists what a registry holds or searches it, or Docker Hub, by name; `registry_tags` lists the tags of an image there, with their sizes; `registry_image_delete` deletes a tag, and names the other tags that went with it
- `image_push` pushes an image that is on a host to a registry Dockhand keeps, and reads the registry back to see that it is there
- a registry that turns Dockhand's login away is said to have, where Dockhand's own answer read as its login refusing the caller
- `schedule_list` lists everything Dockhand does by itself, with when each next runs and how its latest run went, and `schedule_history` the runs, narrowed by type, host, outcome and time, or one run with what it logged
- `schedule_run` runs a schedule now, `schedule_set` switches one off or on, `schedule_delete` removes one and `schedule_history_delete` the record of a run
- `vulnerability_list` lists the known vulnerabilities in the images of every host as the scans last found them, the gravest first, narrowed by how grave, by image, container or stack, or to what a newer version puts right, and says how many images of each host were ever scanned; `image_scan_get` gives the latest scan kept of one image; `vulnerability_export` writes the findings out as CSV, or one image's as SARIF
- `scanner_get` says what each host's images are scanned with and whether the host has the scanner yet, and `scanner_set` sets it: grype, trivy, both or nothing, what they are run with, and the image each is run from
- `image_scan` scans one image now and `image_scan_all` every image on a host, each as a job when it outlasts the wait; both refuse a host set to scan with nothing, where Dockhand answers that it found no vulnerabilities
- `scanner_delete` takes the scanners' images and databases off a host and `scanner_cache_clear` removes their databases everywhere, each after saying what would go
- `notification_list` lists the ways Dockhand tells people what happened, mail or an address of another service, with where each sends, the events it is told of and the hosts it is tied to; `notification_create`, `notification_edit` and `notification_delete` save, change and remove one; `notification_link` ties one to a host for the events named, which is the one way it hears of that host, and `notification_link_delete` unties it
- `notification_test` sends a test for real through a channel, saved or not yet, or sets an event off for a host and says how many channels took it
- an address a channel sends to is listed by its service and host alone unless asked for whole, since the rest of it is its token, and an event that would reach nobody is refused with the reason
- `user_list` lists the users of the Dockhand, `user_create` makes one, `user_edit` changes its name, password and details and switches it off or on, and `user_delete` removes one with its API tokens; the last user that is both switched on and an administrator is left as it is, where Dockhand would take it away and could leave nobody able to sign in
- `login_get` says whether the login is on, how long a session lasts and what whoever signs in is offered, and `login_set` sets them: switching the login on or off needs `confirm`, is not done on unless a user exists who could sign in, and says when this server itself was turned away by it; `token_list` lists the API tokens of the user this server signs in as
- `sso_list`, `sso_create`, `sso_edit` and `sso_delete` list, save, change and remove the single sign-on (OpenID Connect) providers Dockhand keeps, whose secrets are never given back
- `server_update_check` asks the Dockhand whether a newer version of itself is out, and says so when it could not look, which Dockhand answers the same way as "none is out"; `server_about` reads its licence and privacy policy a part at a time and lists the software it is built from, counted by licence
- `stack_create` with `dry_run` says where Dockhand would keep the compose file
- `image_scan` says when the scanner was stopped before it finished, most often for want of memory on the host, instead of quoting the end of the scanner's log
- `settings_get` lists every setting of the Dockhand itself by name, the ones for newer versions of an image among them, and `settings_set` changes the ones named: a schedule and a time zone are checked before they are sent, since Dockhand saves ones it cannot use, and a value Dockhand does not take as given is put back and said
- `template_list` searches the app templates Dockhand has and `template_get` gives one in full with the compose file for it, saying when Dockhand wrote a volume that is none; `template_source_list`, `template_source_create`, `template_source_edit` and `template_source_delete` list, add, change and remove the sources they come from, counting what came of each, since Dockhand says nothing of a source it could not read
- `env_create` adds a host Dockhand cannot reach itself, as one whose Hawser agent calls in (`hawser-edge`), and answers the token the agent is to call in with, once; `agent_list` lists the agents that are connected, the hosts still waited for and the tokens; `agent_token_create` makes or replaces a host's token and `agent_token_delete` revokes one, each saying first which agent it would cut off
- `env_disk` says what a host's Docker disk holds, its images, containers, volumes and build cache, how much of each nothing uses and the biggest of each: the one place a volume's size is told
- `server_files` lists a directory on Dockhand's own filesystem, where the compose files of its stacks lie, `server_read` reads a text file there with passwords and keys hidden, and `server_mkdir` makes a folder there
- `env_test` and `env_create` say which Docker sockets Dockhand finds on its own machine when the one asked for is not there
- `env_get` describes one Docker host in full: how Dockhand reaches it, the machine and the Docker on it as they answer now, and what Dockhand does for it by itself; `env_edit` changes its name, its labels, its public address, what is collected from it and how it is reached, and has Dockhand try the new way; `env_schedules` sets its timezone, when its containers are checked for newer images and whether they are then updated unasked, when its images are pruned, and when a filling disk is warned of, refusing a time no scheduler reads
- `image_list` lists the images of every host with their names, size and how many containers were made from each, or only the ones nothing uses, and `image_get` describes one in full: its digests, labels, the steps it was built from and the containers made from it
- `image_pull` pulls an image to a host and says whether the host now has a newer one; `image_tag` gives an image another name as well; `image_delete` removes one with every name it goes by, after saying what would go; `image_prune` removes the images a host no longer uses, after listing them
- `volume_list` and `volume_get` describe the volumes of every host with the stack that made each and the containers that mount it; `volume_files` lists what is in one and `volume_read` reads a text file in it, with passwords and keys hidden; `volume_create`, `volume_clone`, `volume_delete` and `volume_prune` make, copy and remove them
- `network_list` and `network_get` describe the networks of every host with the containers on each, stopped ones included, and each one's address there; `network_create`, `network_connect`, `network_disconnect`, `network_delete` and `network_prune` make, join, leave and remove them
- `network_prune` and `network_delete` will not take a network a stopped container is on unless told to, since Docker would and the container could then not be started
- `stack_get` describes one compose stack in full: how Dockhand comes to have it, its compose file and where that is kept, its variables, its last deploy, and for a stack Dockhand only found, where the host says it came from; `stack_validate` checks a compose file, a stack's own or text not yet saved, with Dockhand's own checks, and lists the variables it needs against the ones the stack gives; `stack_deploys` lists each time Dockhand brought a stack up, and what compose printed during one
- `stack_create` makes a stack from the text of a compose file, with a .env file and secrets, and brings it up; `stack_edit` changes its compose file, its .env file and its secrets, keeping the secrets it is not given; `stack_deploy` brings a stack up from its file, which is how a change takes effect; `stack_down` removes its containers and networks and keeps its file
- `stack_scan` looks through a folder on Dockhand's own filesystem for compose files, and `stack_adopt` gives Dockhand the file of a stack someone else brought up, where the file lies and without touching what runs; `stack_move` moves a stack's files to another folder; `stack_delete` removes a stack, after saying what would go; `stack_deploys_delete` removes the record of one deploy
- `stack_create` refuses a name a stack on the host already has, `stack_move` refuses a folder that is already there unless told to write over it, and `stack_create` and `stack_edit` refuse a compose file compose would not take: Dockhand left to itself takes over the name, writes over the files and saves the broken file without a word
- `container_stats` measures what each running container is using right now, the heaviest first, and `container_sizes` what each takes on disk and has written inside itself; `container_top` lists the processes in one; `container_files` lists a directory inside one and `container_read` reads a text file there, with passwords and keys hidden
- `container_events` lists what containers did and when, on every host or one, narrowed by name, action and time: each time one was made, started, died and with what exit code, was killed and by what signal, restarted, renamed or removed, and for containers that are gone as well; `container_events_clear` clears that record, after saying how much would go
- `container_pause` and `container_unpause` hold a container still and let it go on; `container_rename` gives it another name; `container_exec` runs one command in it and gives what it printed and exited with, and says which shells the container has when the one asked for is missing; `container_delete` removes one, after saying what would go, and `container_prune` every one on a host that is not running, after listing them
- `container_create` makes a container from an image and starts it, with its command, variables, published ports, mounts, networks, restart policy and labels, pulling the image first when the host has not got it; `container_compose` writes a container out as a compose file
- `container_edit` changes a container's variables, labels, published ports, mounts or command by having it made again with everything else kept, and `container_limits` sets its memory, processors and restart policy as it runs
- `container_updates` lists the containers a newer image is to be had for, as Dockhand last checked or checked now, with the newer version tags and what they changed where the image says where its source is; `container_update` pulls the newer image and makes the container again from it, and touches nothing when the pull brings nothing newer; `container_updates_clear` forgets what was noted
- `container_autoupdate` lists the containers Dockhand updates by itself and when, and `container_autoupdate_set` sets, changes or stops that schedule, refusing a cron expression no scheduler reads, which Dockhand left to itself saves and never runs
- `container_file_write` writes a text file into a container and `container_file_upload` sends files in from the machine the tool runs on, both into a stopped container as well; `container_file_mkdir`, `container_file_move` and `container_file_perms` make a directory, move or rename, and set permissions and owner; `container_file_delete` removes a file or a directory, after saying what is there; `container_file_download` writes a file, or a whole directory as an archive, to the machine the tool runs on
- `tag_list` lists the tags Dockhand keeps, each with the containers and the stacks it is on, host by host; `tag_create` makes one and `tag_edit` changes its name, colour and icon; `tag_assign` sets the tags of one container or stack, whole or a tag at a time; `tag_delete` removes one from everything that has it
- a tag is given only to a name a container or a stack has, and only a tag there is: Dockhand left to itself saves tags under a name that is nothing's, and answers a tag there is none of with an error after taking away every tag the name had, which `tag_assign` puts back should it happen; a colour that is none of Dockhand's sixteen is refused, which Dockhand would make slate or quietly ignore
- `label_list` lists the labels Dockhand groups its hosts by, each with its colour and the hosts that have it; `label_edit` renames one on every host that has it, colours it, or with `merge` makes two one; `label_assign` gives one to hosts and takes it from others; `label_delete` removes one from every host
- a label is never renamed to the name it has, which Dockhand takes it from every host for, nor given a colour Dockhand does not know, which it takes the label's colour away for while answering that it was set; a host Dockhand does not manage is refused rather than passed over
- `config_set_list` lists the bundles of container settings Dockhand keeps, each in full in the words the tools that make a container take, with the values of secrets hidden unless `reveal_secrets` asks for them; `config_set_create` saves one and `config_set_edit` changes it, a variable or a label at a time and its ports and mounts whole, each checked first since Dockhand checks nothing of a set but its name; `config_set_delete` removes one
- `icon_list` lists what was given an icon on each host, the host itself, its containers and its stacks; `icon_search` finds an icon among selfh.st's by words; `icon_set` gives a container, a stack or a host an icon by name, or sends a picture for it from this machine; `icon_download` writes the picture of an icon to this machine; `icon_delete` removes one
- an icon is given only to a container or a stack that is there, a name is checked for being one and a picture for being a picture: Dockhand left to itself saves any text and, for a host, any file, keeps an icon for a name nothing has, and for a stack then lists a stack of that name with nothing in it
- a stack Dockhand only found is given an icon only with `even_found`, since Dockhand then keeps a record of it for good; `stack_get` says such a stack is kept as `external`, `stack_adopt` gives it its file by saving the file where it lies, where Dockhand's own adoption would make a second stack of it, and `stack_delete` removes it as it removes a found one
- `preferences_get` reads what Dockhand's web interface remembers, the order of hosts and of tags, the sidebar, the columns of each grid, whether the schedules page hides Dockhand's own jobs, the dashboard with where each host's tile is, and the pages it opens on, and `preferences_set` changes any of them, each whole, read back afterwards
- an order or a tile is set only for hosts and tags there are, a layout and a page only to ones Dockhand has: Dockhand left to itself saves an order that names nothing, any text as a layout, and any list as the dashboard's tiles; a page is forgotten by setting it empty, which the tool sends as the null Dockhand asks for
- `favorite_list` lists the containers and the groups of containers kept at hand for each host's log view, and `favorite_set` sets them for one host, whole and in order: Dockhand keeps both kinds in one list and its own reordering of either drops the other, so the list is always written as one; a name no container has is refused unless it is kept already
- `secret_provider_list` lists the secret stores Dockhand loads stacks' secrets from, each with its kind, where it is, the stacks that use it and whether it is the default, never with what it signs in with; `secret_provider_test` has Dockhand try one, saved or not yet; `secret_provider_keys` lists the names of the secrets one holds at a path, never their values; `secret_provider_create`, `secret_provider_edit` and `secret_provider_delete` save, change and remove one
- a stack is given its secrets by a provider: `stack_create` and `stack_edit` take `secret_provider` and `secret_path`, asking the provider first whether anything is at the path, `stack_get` says which provider and path a stack has and the names its last deploy was given, and `stack_validate` counts what the provider gives as given, where Dockhand's own check calls each missing
- a provider is tried before it is saved or changed, since Dockhand saves one it cannot reach and a stack bound to it is then not deployed; a provider's address is changed only with its token given again, since Dockhand keeps the token and sends it to the new address; and one that stacks use is removed only with `even_used`, after the stacks are named, since Dockhand takes each off it without a word and their next deploy succeeds with those variables empty
- a deploy that fails for a stack with a secret provider says so, where Dockhand says only that the deploy failed; a new `.env` file that leaves out the path a stack's secrets are loaded from keeps it, and says so
- `image_export` writes an image on a host to a tar archive on this machine, gzipped when the file's name says so, under whichever of its names is asked for; `image_load` loads an archive onto a host and reads back that the image is there, after saying which names the archive holds and which the host has already; `volume_export` writes what a volume holds, or a part of it, to an archive. None writes over a file that is there
- a volume there is none of is refused by `volume_export`, where Dockhand asked to export one makes it and answers an empty archive; and the volume tools that read a volume through Dockhand's helper container now wait until the helper is gone, since Dockhand says it is before it is and a volume it still has cannot be removed
- `git_credential_list`, `git_credential_create`, `git_credential_edit` and `git_credential_delete` list, save, change and remove what Dockhand signs in to a git server with; a password or key is never given back, a change is followed by trying every repository fetched with the credential, and one in use is removed only after those repositories are named
- `git_repository_list`, `git_repository_create`, `git_repository_edit` and `git_repository_delete` list, save, change and remove the git repositories Dockhand keeps, each tried before it is saved where Dockhand saves any; `git_repository_test` says whether Dockhand can fetch one, saved or not yet, with its branches, and `git_repository_variables` reads what the `.env` files in one would give a stack; a password or token written into an address is hidden unless asked for
- `git_stack_list` and `git_stack_get` list and describe the stacks Dockhand deploys from git: the commit last fetched, the one each runs from and, when asked, the newest on its branch; `git_stack_create` makes one from a repository and brings it up, `git_stack_edit` changes its branch, paths, schedule, webhook, variables, secrets and secret provider, `git_stack_sync` fetches the newest commit and says what a deploy would change, `git_stack_deploy` fetches and deploys, or only when there is something new, and `git_stack_delete` has Dockhand forget a stack is from git and leave its containers
- a git stack is renamed only when it has no containers and to a name no stack has, where Dockhand renames one that runs and leaves its containers behind, and half-does a rename it refuses; a webhook's secret is hidden unless asked for; and the values of a stack's secrets, which Dockhand answers with one of its two deploy calls, are never read
- `stack_edit` refuses a stack deployed from git, whose files are replaced from the repository at each deploy and whose own variables saving its secrets the ordinary way would drop; `stack_get`, `stack_deploy` and `stack_delete` say what a git stack with no files yet is, where they said it was found on the host
- the file tools look at a path before they put anything there: Dockhand left to itself writes a file in the place of a directory and takes everything in the directory with it, and moves a file over another without a word; a directory is always refused and anything else is replaced only with `overwrite`
- a container that is Dockhand itself, or one of its agents, is not made again through Dockhand, which would stop the work part way
- slow work is left running rather than waited on without end: a pull, a prune, a deploy or a down is waited for up to `wait` seconds, 50 unless said, and one still going then answers with a job id; `job_get` says how a job is going and how it ended, and `job_cancel` asks it to stop
- passwords, tokens and keys in a container's variables, command line, log lines, files and what a command run in it printed, and in a stack's compose file, variables and deploy logs, are hidden unless `reveal_secrets` asks for them; a variable to be filled in, `${DB_PASSWORD}`, is shown as it is written, since the name of a password is not the password
- every tool only reads unless `--enable-write` is given, and none deletes without `--enable-delete` beside it
- a tool about a Docker host takes `env`, by name or number, and a read asks every host when none is named
- `sdk/dockhand`, a Go client for every call of the Dockhand API, generated by pandorest from the document Dockhand serves about itself, with what that document gets wrong fixed by named workarounds
- the `serve`, `tools`, `info` and `version` commands, settings from flags, `DOCKHAND_*` environment variables and `.dockhand-mcp` files in `$HOME` and the working directory, and a container image
